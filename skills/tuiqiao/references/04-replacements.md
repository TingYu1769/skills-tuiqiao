# 高频词的替换与近义词辨析

这张卡是查词用的。每个高频词或框架先列出它的正当用法（留着），再按它在句子里起的作用给几种改法，最后提醒不要换成什么。某个词算不算 AI 口癖、强弱如何，查 02-ai-tics。为什么在语法上要改，查 03-word-syntax 对应的 W 规则。本卡编号 R1–R24，后面另有一节技术文的近义词辨析。

先判断这个词在这一句里起什么作用，同一个“对应”，在映射表里是准的，在“每一层都有对应的防法”里是空的。能删就先删，删不掉再换主语、改结构，最后才换词。改完整篇后统计换进去的词，同一个替换词在一页里出现三次以上，就换一种改法（01-boundaries）。表里有些替换词本身也是高频词（“给出”和“提供”，“正是”和“就是”），互相替换只是把口癖挪了个位置。

每条后面的“样本”频次是一部中文技术书稿的实测，统计范围是正文（约 4.3 万汉字），不含代码块和表格，含复合词时另作说明。

## 一、动词

**R1 进行（作出、加以、予以、开展）** 【名家】【规范】【改稿】 样本只有 1 处“进行”，没有“作出”“加以”“予以”。

留着：持续而正式的活动做谓语（评测正在进行）；状语或宾语很长、需要一个动词托住（对 128 条轨迹逐条进行人工复核）。

改法看后面的名词。名词能当动词的，直接还原（对检索结果进行重排序 → 重排检索结果）。宾语很长的，把它提到前面做话题（对所有超时的请求进行重试 → 超时的请求都要重试）。表示正在做的，用“在”加动词，“这两条查询都是在对整张表进行扫描”改成“这两条查询都是在扫描整张表”（自拟）。动作带次数的，把次数放到动词后面（进行三次采样 → 采样三次）。

别换成开展、展开、实施、执行，它们是同一类万能动词。

**R2 实现** 【改稿】【经验】 样本 15 处，几乎都是 implement 义。

留着：implement 义（用 Rust 重新实现解析器）；名词“实现”（接口的实现、缓存层有两套实现并存）。

“实现了 X 的提升（降低、增长）”改成“X 提升了”，同段有数字就把数字放进谓语。baibanbao/qu-ai-wei 的例子是“新系统实现了效率的提升。处理时间从两小时缩短到四十分钟”，改成“新系统把处理时间从两小时缩短到四十分钟”。“实现目标”改“达到目标”或“做到”，“实现覆盖”改“覆盖”。“通过 X 实现 Y”改成“用 X 做到 Y”，或者让 X 做主语（通过缓存实现了重复请求的免计算 → 有了缓存，重复的请求不必重算）。

别换成“达成”“完成了……的”，后者又回到了名词化。

**R3 给出** 【改稿】 样本 13 处。

留着：数学写作里摆出一个成形的对象（给出定义、给出证明、给出反例，又如“原论文给出了方差的无偏估计”，自拟）；证据主语后面的“给出的数字是”“给出的理由是”（自拟：“维护者给出的理由是”，这类主语承载归因，见 P11）；本来通顺的搭配（每道题都要给出答案）。

动作名词前的“给出”还原成动词：给出判断 → 判断，给出建议 → 建议，给出评价 → 评价。“给出分数”不带公式时改“打分”，带公式时改“算出分数 $F_1=2PR/(P+R)$”（03-word-syntax W1）。

别换成“提供”，它在这个位置同样空转。

**R4 提供** 【改稿】【经验】 样本 24 处，几乎都是接口和产品提供功能。

留着：接口、服务、协议、产品提供功能或原语（自拟：Redis 提供五种基本数据类型，这个库同时提供同步和异步两套接口）。

“提供 + 动作名词”还原成动词：为用户提供帮助 → 帮助用户，提供支持 → 支持，提供保障 → 保证。“为……提供了一种新思路（新视角、新范式）”多半是空话，原文说了思路是什么，就直接写出来，没说就删掉这句的评价部分，并在批注里写“此处材料稀薄”。

别换成“给出”“带来”“赋予”。

**R5 具有（具备、拥有）** 【经验】【名家】 样本 0 处。

留着：数学定义里的“具有性质 P”；法规、标准里的“具有……资格”。

一般改“有”（该系统具有很高的吞吐量 → 该系统吞吐量很高）。带数值的改“为”（具有 $O(n\log n)$ 的时间复杂度 → 时间复杂度为 $O(n\log n)$）。带性质的改形容词谓语（具有较高的可扩展性 → 容易扩展）。“具有重要意义”删掉，或者把意义说具体（02-ai-tics A12）。

**R6 存在（存在着、有着）** 【名家】【实测】【改稿】 样本 18 处“存在”，都是本义。

留着：量词（存在 $x$ 使得）；实际存在与否（自拟：键在缓存里不存在，就回源查询；打开一个不存在的路径会报错）。

“存在 + 问题、风险、差异、偏差”改“有”（存在一定的风险 → 有风险）。表示两者不同的改形容词（两种实现存在差异 → 两种实现不同）。“存在着”“有着”的“着”删掉，余光中的例子“杜甫的诗中存在着浓厚的人民性”，用“有”就够了。lieflat 测得“存在着、有着”在 AI 文本里每千字只有 0.04 处【实测】，改它是因为空转。

**R7 对应** 【改稿】 样本 26 处。

留着：映射表、配对、图例（自拟：状态码 404 对应“资源不存在”，图注“颜色对应三个可用区”）；数过两边项数的“一一对应”。

改法按真实的关系选。用来检查的，写“检查”（每个字段都有对应的检查办法 → 每个字段都有检查的办法）。冲着某个问题定的，写“针对”（自拟：三条索引规则各自对应一类慢查询 → 三条索引规则各自针对一类慢查询）。由几部分组成的，写“拆成”（自拟：一行访问日志正好对应时间、路径、状态码三段 → 正好拆成时间、路径、状态码三段）。属于某一类的，写“落在”“属于”。做定语的“对应的”，多数直接删（自拟：每种优化都能在编译流水线里找到对应的位置 → 每种优化都能在编译流水线里找到位置）。

别换成“相应”“相对应”“匹配”，意思同样含糊。

**R8 影响** 【名家】【改稿】 样本 9 处。

留着：方向不定或者两个方向都有（竺可桢《大自然的语言》：“经度的差异是影响物候的第二个因素”，下文说近海的地方冬天温和，春天反而寒冷）；计数（自拟：“3% 的请求受到影响，平均延迟多了 40 毫秒”，后半句已经说了怎么影响）。

方向已知时，换成真正发生的那个动词：拖慢、放大、掩盖、抬高、压低、决定、改变（T2）。“对 X 产生影响”改“影响 X”。“产生了深远影响”删（02-ai-tics A12）。前提是原文或上下文已经交代了影响的方向，否则保留“影响”，不替作者猜。

**R9 被称为（被叫作、被命名为）** 【规范】【改稿】 样本 3 处。

留着：“称为”“叫作”本身是下定义的词（P1），去掉的只是“被”。

改成“称为”“叫作”或“叫”（这一现象被称为缓存雪崩 → 这种现象叫作缓存雪崩，自拟）。命名者有交代价值时，让命名者做主语，竺可桢《大自然的语言》的“这些自然现象，我国古代劳动人民称它为物候”就是这样写的。“命名为”只用于有人特意起名的场合。几种说法在一页里轮着用。

## 二、介词与框架

**R10 通过** 【规范】【名家】【改稿】 样本 65 处，绝大多数表示渠道。

留着：渠道和途径（通过 API 调用、服务端通过 SSE 推送、进程之间通过管道通信、前端只能通过接口读写数据）；动词（测试全部通过）。

表示手段的改“用”（通过使用缓存来减少调用 → 用缓存减少调用）。表示依靠的改“靠”。表示先做一件事再出结果的，改成“……后”（通过引入反思步骤，使成功率提高了 12% → 引入反思步骤后，成功率提高了 12%）。“通过……使”“通过……从而”只留一端，补回主语（03-word-syntax W6）。

别换成“借助”“经由”“依托”。

**R11 作为** 【名家】【实测】【改稿】 样本 17 处，都是正当用法。

留着：动词（作为下一步的输入；把查询结果作为缓存写回 Redis）；表示身份、且和主语是同一个东西（HTTP/3 作为 RFC 9114 发布；网关作为唯一入口，对外暴露接口）。

悬垂的拆开重写（作为一种训练范式，我们提出…… → 我们提出一种训练范式……）。做定语的改判断句，余光中把“作为竹林七贤之一的刘伶以嗜酒闻名”改成“刘伶是竹林七贤之一，以嗜酒闻名”。表示身份的换“身为”或“是”。“可以作为……的总结”这类引导句，按 R14 处理。

**R12 对于、关于、有关** 【名家】【规范】【实测】 样本“对于”0 处，“关于”2 处。

留着：标题“关于 X”；确实在划定范围（自拟：“对只读的报表查询来说，加一层缓存就够了”）；搭配上需要介词的，用单音节“对”（对长文本有效、对结果负责）。

名词短语直接做话题（对于长任务来说，关键是上下文管理 → 长任务的关键在于上下文管理）。“关于 X 的讨论（研究、分析）”改成“讨论 X”。“有关”删掉，固定说法（有关部门）除外。

别换成“针对……”“围绕……”放在句首，它们照样是话题壳。humanizer-zh-next 把“围绕……展开”列为同类的空转框架。

**R13 从……角度看（就……而言、在……方面、在……层面）** 【实测】【改稿】 样本“角度”4 处。

留着：真有两种视角并列（梁启超《敬业与乐业》：“事的名称，从俗人眼里看来，有高下；事的性质，从学理上解剖起来，并没有高下”）；前文刚从另一方讲过，需要标出视角切换（自拟：上一句刚讲完客户端怎样重试，下一句写“从服务端这一侧看，重复的请求必须幂等”）。

删掉框架（自拟：从架构的角度看，微服务把模块之间的调用搬到了网络上 → 微服务把模块之间的调用搬到了网络上，SKILL.md W5）。视角的主人做主语（就用户而言，延迟最重要 → 用户最在乎延迟）。“在性能方面有优势”改“性能更好”（03-word-syntax W7）。

别换成“从……来看”“站在……立场”。

## 三、副词与评论语

**R14 可以** 【改稿】 样本 131 处，多数表示能力或选择。

留着：能力（这个进程可以读写文件、监听端口）；许可和选择（学习率也可以按步数衰减）；并列的可选项（同一条慢查询，可以加索引，也可以改写 SQL）；规范和设计文档里表示允许的“可”（08-genres）。

作者自己选定的说法，改成直接断言（这个现象可以用局部性原理解释 → 局部性原理讲的就是这件事，自拟）。“可以看作”“可以理解为”改成判断句（物化视图可以看作预先算好的查询结果 → 物化视图是预先算好的查询结果），或者改“相当于”。“可以这样理解：”这类引导句，删掉以后直接说内容。“可以作为这一节的总结”整句删掉，让引文自己出场。四种改法轮着用，不要全改成“就是”。

**R15 正是、恰恰、正好** 【改稿】 样本“正是”18 处，“恰恰”0 处。

留着：“正好”表示数量、时间恰好（正好 8 次）；确认一个读者会怀疑的同一性，这种情形很少。

删掉，多数句子不受影响（第 2 点正是缓存失效的起因 → 第 2 点是缓存失效的起因，自拟）。倒装，让被强调的东西落到句尾（这正是把索引建在外键上的意义 → 把索引建在外键上，意义就在这里，自拟）。回指上文的“这正是前面说的 X”，改成括号回指，或者并进前一句（自拟：写请求只发主库，读请求分给从库。这正是前面说的读写分离 → 写请求只发主库，读请求分给从库，即前面说的读写分离）。指认内容的“记录的正是这三类指标”，改成“记录的是这三类指标”。

别把所有“正是”都换成“就是”，SKILL.md 点名过这种新口癖。

**R16 就、便** 【实测】【改稿】 样本“便”13 处（含“即便”“方便”“便宜”）。

留着：条件呼应（只要……就）；指代（这就是 X）；早、快、容易、现成（本身就会、这里就能找到）；时间紧接（一写好就提交）。

纯强调的“就”删掉（这条索引就没有用上 → 这条索引没有用上，自拟）。白话段落里的“便”改“就”（命中缓存便直接返回 → 命中缓存就直接返回，自拟）。“就是”只做系词强调时改“是”。lieflat 实测 AI 用的“就”比人少（每千字 2.93 对 6.45）【实测】，这只说明不必删光，不说明要补，不为“像人写的”补“就”（02-ai-tics C9）。

**R17 显著、明显** 【规范】【改稿】 样本“显著”1 处，“明显”5 处。

留着：做过统计检验的“显著”；看得出来、有数字支撑的“明显”（自拟：加索引后查询明显变快，从 800 毫秒降到 30 毫秒）。

没做检验的“显著”改“明显”（自拟：内存占用随连接数显著增长 → 内存占用随连接数明显增长）。同段有数字的，用数字代替程度词（显著提升 → 从 52 升到 68，数字须是原文已有的）。“大幅”“极大地”同样处理。

**R18 值得注意的是（需要指出的是、有意思的是、还有一个变化值得一提）** 【实测】【改稿】 样本 3 处“值得注意”。

留着：没有正当用法（02-ai-tics A3）。

删掉，让内容自己开头（下面两例自拟）。“还有一个变化值得一提：上一节提到的旧版连接池，现在默认只在兼容模式下启用”，删去领句，从“上一节提到的”起句。“值得注意的是回滚之后发生的事：它不只换回旧版本，还会清空下面三类缓存：……”，改成“回滚不只换回旧版本，还会清空下面三类缓存：……”，原句的两个冒号只剩引出列表的一个。要标出一件事反常，在句子里用“但”“却”说出反常的地方。

## 四、复述与对比

**R19 也就是、换言之、换句话说、这意味着** 【实测】【改稿】 样本“也就是”13 处，“换言之”1 处，“这意味着”2 处。

留着：在术语和日常说法之间搭桥（自拟，下同：“**Shard**（分片，也就是整张表切下来的一块）”）；带来新推论（“存储引擎只追加写入，不原地修改。这意味着，删除一条记录也要追加一条墓碑记录”，P9）；把记号落到实物上（“`HEAD` 指向当前检出的位置，也就是工作区停在哪个分支、哪个提交上”）。

后文和前句同义的，删掉整句或并进前句（自拟，下同：“服务端不保存会话。换言之，每个请求都要自带全部状态”，删掉“换言之”，见 03-word-syntax W1）。同位解释改成括号（每个批次算一步，也就是一次前向加一次反向传播 → 每个批次算一步（一次前向加一次反向传播））。解释英文术语的，把释义放到冒号后面（这种情况叫 thundering herd，也就是缓存一失效，所有请求同时涌向数据库 → 这种情况叫 thundering herd：缓存一失效，所有请求同时涌向数据库）。括号、冒号、“即”三种轮着用，一页里不要全换成冒号。

**R20 不是……而是（并非……而是、不在于……而在于、与其说……不如说）** 【实测】【改稿】 样本“而是”13 处，多数在纠正误解。

留着：纠正读者真会有的误解（自拟：“`DELETE` 并不是立刻把数据从磁盘上抹掉，而是先打上删除标记”“`volatile` 保证的不是原子性，而是可见性”，P8）。

没有误解可纠的，直接正面说（真正的壁垒不是技术，而是认知 → 真正的壁垒是认知，SKILL.md）。否定的一面确有信息、又不是读者的误解时，把正面判断放前面，否定放后面做补充，梁启超《敬业与乐业》的“须知苦乐全在主观的心，不在客观的事”就是这个语序。判断的细则见 02-ai-tics A1。

## 五、指代、量词与名词

**R21 这、这一** 【改稿】 样本“这一 + 名词”62 处。

留着：“这”指一整件事、省掉读者会迷路（这在上一节已经讲过）；同位结构（自拟：“都服从‘先写日志，再改数据’这一条”）；“这一步”“这一层”“这一侧”这类和步骤、位置连在一起的说法。

“这一 + 名词”改成“这个”“这种”，或者直接用名词（这一现象 → 这种现象；把这一思路推广到多个节点之间 → 把这个思路推广到多个节点之间，自拟）。句首的“这”能从上文接上主语，就省掉（这和上一节讲的预取是同一个思路 → 和上一节讲的预取是同一个思路，自拟）。把“这”倒到句尾收束（R15 的倒装）。指代有歧义时重复名词。“此”“该”“其”改“这”或省略（03-word-syntax W17）。

**R22 一个、一种** 【名家】【改稿】 样本“一个”380 处，“一种”36 处。

留着：计数；引入一个新的具体对象（加一个 `--dry-run` 参数）；定义句里引出类别（自拟的“B 树是一种多路平衡查找树”，梁思成《中国建筑的特征》的“所以我们说它是一种建筑上的‘文法’”）；“一种……另一种”的分类。

泛指名词前的删掉（重启一个服务 → 重启服务）。评价句改主谓（这是一个很重要的问题 → 这个问题很重要）。“以一种……的方式 + 动词”改成副词或补语（以一种更稳定的方式运行 → 运行得更稳定）。“提供了一种可能”这类修饰空名词的“一种”，连同空名词一起删。

**R23 性、化、度** 【名家】【实测】【改稿】

留着：能定义或度量、全文当术语用的（泛化、形式化、序列化、持久化、确定性、随机性、可靠性、可用性、复杂度、并发度）。

形容词硬转成的名词改回形容词做谓语（该方法的简单性使其易于实现 → 该方法简单，容易实现）。“存在稳定性问题”这类说法，原文交代了具体表现（崩溃、超时）就写表现，没交代就改成“不够稳定”。“进行结构化处理”改“整理成结构化数据”或直接用“结构化”做动词。生造的“度”还原成原词，余光中的例子是“知名度”还原成“名气”。

**R24 关键、核心、本质（根本、最根本、归根结底）** 【改稿】【经验】 样本“关键”11 处，“核心”5 处，“本质”6 处。

留着：字面义（关键信息、SQL 关键字、核心模块）；排序（自拟：“几项优化里最关键的，是把热点数据放进内存”）；术语译名（core dump 译作“核心转储”）；说明两样名字不同的东西其实是一回事的“本质上”（自拟：“所谓乐观锁，本质上就是带版本号的条件更新”）。

做强调用的“本质上”删掉：“这个函数本质上是没有副作用的”改成“这个函数没有副作用”，“这本质上是一个查表操作”改成“这是查表操作”（自拟）。“关键在于 X”“核心是 X”，让 X 直接做谓语或主语。“最根本的”多数删掉，留着时要能说出和什么比。

别换成“实质上”“说到底”“归根结底”。“说到底”在 SKILL.md 的翻案腔触发标记里，“归根结底”在 02-ai-tics B11 的揭晓式副词里。

## 六、技术文的近义词辨析

**证明、表明、显示、说明、提示。** “证明”只用于数学证明，或者在逻辑上排除了其他可能的论证（自拟：测试只跑了正常输入，“证明不了函数在空列表上也能工作”）。实验结果用“表明”或“显示”，前者带着作者的推断，后者只报告看到的数据（自拟：“压测结果显示，并发到 2000 时 P99 延迟开始上升”）。“说明”用于作者的解释和推论。证据弱时用“提示”（P3）。把“表明”改成“证明”，就是越证据断言（02-ai-tics A12）。

**估计、预测、判断、推断、评估、评测。** “估计”是统计意义上从样本推一个量（自拟：“真实的命中率不知道，只能从抽样日志估计”；“无偏估计”）。“预测”指向尚未发生或尚未生成的东西（预测下一个 token）。“判断”给出是或否、属于哪一类（竺可桢《大自然的语言》：“根据这些物候观测资料，可以判断北京地区 1962 年农业季节来得较晚”）。“推断”是从证据推结论。“评估”是对质量的整体衡量，“评测”专指在基准上跑分。A/B 测试“估计”的是两组转化率之差，写成“预测”或“判断”都不准（自拟）。

**即、例如、比如、包括、等。** “即”表示等同，后面要列全（自拟：“只改了两个参数，即连接池上限和超时时间”，两项正好列全）。“例如”“比如”只举其中几个，原文或用户约定统一用其中一个时，改稿沿用。“包括”后面的项可以不全，要表示列全写“共”“分别是”。省略号不和“等”连用（05-punctuation）。

**用、使用、采用、利用、借助、基于。** 默认用“用”。宾语长或者做名词时用“使用”（使用只读副本时）。“采用”表示在几种方案里选定一种。“利用”在讲安全漏洞时常带“钻空子”的意思（利用缓冲区溢出的漏洞，自拟），中性场合少用。“借助”强调外力。“基于”表示以某物为底（基于 JSON-RPC 2.0、基于 LLVM 的编译器），“基于此”做连接词是空转，改“所以”或删掉。

**执行、运行、调用、启动、跑。** 命令、动作、指令用“执行”（Shell 执行命令、CPU 执行指令）。程序、进程、环境用“运行”（在本地运行、运行测试套件）。函数、接口、模型、工具用“调用”。进程和服务开始用“启动”。原文里“跑”已经定型的（跑测试、每个配置跑 5 次），保留，作者叙述以外不新增。

**提高、提升、改善、增强、优化。** 数值变化用“提高”或“提升”（成功率提高了 12%）。由坏变好的定性变化用“改善”。能力、安全性用“增强”。“优化”指有意去优化某个目标（算子优化、RL 优化奖励），自然变好不叫优化。

**导致、造成、引起、使。** “导致”“造成”多用于不好的结果。中性的前因后果，用顺序并列或“……后”，不必加因果动词（03-word-syntax W3）。“使”前面必须有主语（W6）。

**难点、问题、挑战、瓶颈。** “挑战”多是 challenge 的直译（解决挑战、面临挑战），改“难点”“难处”或直接说难在哪里。“瓶颈”只用于真正限制总体速度或规模的那一环（自拟：超过 16 卡以后，卡间通信决定总时长）。

**方法、办法、方案、手段、做法、策略。** “办法”“做法”语体平实。“方案”指一套设计。“手段”指具体的一种操作（重试、熔断、降级三种容错手段）。原文已经把“策略”当术语用的（强化学习的 policy、访问控制的策略），泛指 strategy 时换成“办法”“打算”，免得和术语混淆。

**通常、往往、一般、常常。** “通常”表示默认情况，“往往”表示在某种条件下的倾向，“常常”表示频率。这些都是证据性限定（P3），按原文的强度选，不为求变化轮换。
