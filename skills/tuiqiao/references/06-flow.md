# 行文思路

这张卡管段落和论证的组织：一节怎么开头，一段之内句子怎么排，段与段怎么接，一节怎么收尾。它展开 SKILL.md 精简规则里的 F1–F11，新增 F12（章首导读）。条目按改稿时所处的位置排列，编号因此不连续：开头查 F1、F5、F12，段落内部查 F2、F3、F4、F7、F8，段与段之间查 F9、F6、F11，节尾查 F10。段首连接词、元话语、空转领句、金句收尾这些表面信号在 02-ai-tics 里认（A4、A6、A7、A11），这里讲背后的结构问题。句内用词查 03-word-syntax，比喻、对照、长短句查 07-elegance，各体裁的固定结构查 08-genres。01-boundaries 优先于本卡的每一条，第六节列出不经询问不要做的结构调整。

例句分两类。名家的引文逐字录自 `exemplars/` 下的公版选段和 11-exemplars 里的短引，标明作者和篇名。标“自拟”的是为演示毛病和改法虚构的技术句子，其中诊断第 1、2 步用的是一篇自拟短文（讲缓存读到旧值，分“陈旧读”“发现旧值”两节），后面几条规则还会回到它。证据等级【改稿】指这条改法在一部中文技术书稿的改稿中验证过。

## 一、先诊断，再动手

结构问题先看出来，再决定改不改。这套流程对应 SKILL.md 改稿流程的第二遍，一节一节做。

1. **抽骨架。** 只读每段的前两句，按顺序读下来，看能不能复述本节的论证。可以用脚本抽：

   ```python
   # skel.py　用法：python3 skel.py FILE "#### 陈旧读"
   import re, sys
   path, head = sys.argv[1], sys.argv[2]
   lines = open(path, encoding='utf-8').read().split('\n')
   start = next(i for i, l in enumerate(lines) if l.strip() == head)
   for l in lines[start+1:]:
       if re.match(r'#{2,4} ', l): break
       if not l.strip() or l.startswith(('|', '!', '*图', '$$', '```')): continue
       s = re.findall(r'.+?[。？！](?:\*\*)?|.+$', l.lstrip('> '))
       print('·', ''.join(s[:2])[:160])
   ```

   对自拟短文的“陈旧读”一节（七段，正文只写出要演示的句子，其余用省略号代替）跑出来的骨架是：

   ```text
   · **陈旧读（stale read）指底层数据已经改了，读请求拿到的却还是缓存里的旧副本。** 用上一节的话说，就是缓存和数据库对同一个键给出了两个答案。
   · 写得频繁的数据格外容易读到旧值。缓存只在读的时候填充，写入却随时发生：两次读之间，库里的值可能已经改了好几轮。
   · 关于陈旧读，有三个值得记住的观察。
   · 第一，这不是罕见现象。……
   · 第二，缩短过期时间，效果因读写比例而异：读到旧值的比例能明显下降，但降不到零。某电商团队把库存缓存的过期时间从 10 分钟缩到 30 秒，读到旧库存的比例仍是 6%，和缩短前几乎一样 [2]；一份社交平台的内部报告显示，……从 12% 降到 0.5% [3]；某开源项目的压测里，……从 30% 降到 8% [4]。
   · 第三，旧值会扩散。……
   · 写入侧怎么改、读取侧怎么防，放到下一节讲。这里只需要记住一个原则：**副本越多、过期时间越长，读到旧值的窗口就越大。
   ```

   骨架里看不到第二段后半的“按旧值产生的位置分层”，一段装了两个议题（F4）。第三段只宣布数量（F7）。第四到六段去掉序号，首句自己就能串成论证（F7）。末段在结论前加了一句元话语（F10）。

2. **划主语。** 把一段里每句的句首抄出来，看主语在几个名字之间怎么移动（F3）。

   ```python
   # heads.py　用法：python3 heads.py FILE 行号
   import re, sys
   path, n = sys.argv[1], int(sys.argv[2])
   para = open(path, encoding='utf-8').read().split('\n')[n-1]
   para = re.sub(r'^\*\*[^*]{1,12}\*\*\s*', '', para)   # 去掉段首小标题
   for s in re.findall(r'.+?[。？！]|.+$', para):
       print('·', re.split(r'[，：；]', s.strip())[0][:24])
   ```

   同一篇短文下一节“查日志”一段的结果是：监控只看错误率／某支付公司复盘一年的对账差错／一家云厂商在事故报告里披露／某电商团队统计值班记录／某开源数据库的维护者在邮件列表里说／监控仪表盘也开始单列旧值命中率／查日志也有局限。中间四句的主语都是机构，证据在按来源排队（F8）。到“监控仪表盘也开始单列旧值命中率”，主语换成了另一类东西，后面两句讲的也是另一件事，这里就是拆段的位置（F4）。

3. **查接缝。** 列出每段开头的几个字，标出连接词和元话语，逐个判断（F9）。

   ```bash
   grep -n -E "^(然而|因此|此外|另外|同时|所以|于是|最后|首先|第一|下面|接下来|上一节)" FILE
   ```

   以“所以”“最后”起头的段落，处理各不相同，见 F9。

4. **查节尾。** 每个小节末尾的结论句，依次做标题检验、支撑检验、摘要检验（F10）。

5. **查回指。** 搜出整句的章节回指，看是不是太重、括号放得对不对（F11）。

   ```bash
   grep -n -E "说过|讲过|如前所述|前面讲|上文|上一节" FILE
   ```

6. **公式换成“某某”再读。** Knuth 说许多读者第一遍会跳过公式，所以把公式换成“blah”以后，句子仍应读得通。例如“缓存在时刻某某写入，数据库在时刻某某更新，两者之差某某就是可能读到旧值的窗口”（自拟），换完照样能懂。读不通，说明意思全压在公式上，要请作者补一句文字说明。

7. **划范围。** 诊断出的问题，分清哪些在交给你的范围之内、可以直接改，哪些要先问作者（第六节）。

## 二、开头

**F1 开头直接进入事实或问题** 【名家】【改稿】

触发标记：随着……的快速发展、近年来……受到广泛关注（02-ai-tics B9）；“若先……而只……那么……可以用一句话概括”式的长条件铺垫；“我们可以按照……分为以下……”；“既然……我们便不可避免地触及……”这类把过渡写成仪式的句子。

Williams 讲引言：先给共同的背景，再用“但是”转出问题，问题由一个条件和读者要付的代价组成。Knuth 要求开头一段是全文最好的一段。成立的开头，有的直接陈述事实：

> 梁实秋《雅舍》第一句（据 11-exemplars E39）：到四川来，觉得此地人建造房屋最是经济。
> 竺可桢《大自然的语言》讲纬度的一段（据教材改写本）：首先是纬度。越往北桃花开得越迟，候鸟也来得越晚。

有的先给共同背景，再转出一个有代价的问题，用的就是 Williams 的结构：

> （自拟）上一节说，缓存把大部分读请求挡在了数据库前面。但光挡住读请求还不够：数据一改，缓存里的副本得有人作废，用户才不会看到旧值。

“得有人作废”是条件，“才不会看到旧值”是代价。这句只有起句的“上一节说”可以按 F11 改轻：“缓存把大部分读请求挡在了数据库前面（见上一节）。”

要改的开头：

> 原（自拟）：若先不追究硬件和网络等其他因素，而只回到它最本分的职责，那么缓存所做的事可以用一句话概括：把算过的结果存起来，下次直接返回。
> 改：撇开硬件和网络等其他因素，只看最本分的职责，缓存做的事是：把算过的结果存起来，下次直接返回。

“先不追究硬件和网络等其他因素”限定了讨论范围，改后留成状语，删掉的只有“若……那么”的空架子和“可以用一句话概括”（02-ai-tics B1、A6）。

> 原（自拟）：既然每次请求都要重新带上会话令牌，我们便不可避免地触及 HTTP 最根本的物理属性：**协议本身是无状态的（Stateless）**。
> 改（需作者确认）：每次请求都要重新带上会话令牌，根源在于 HTTP 最根本的属性：**协议本身是无状态的（Stateless）**。

“我们便不可避免地触及”只是仪式。改后把两件事写成因果，这层因果即使有下文支撑，也是改稿者的读法。“物理属性”是作者的比喻，删不删由作者定。两处都写进批注。

改法：(1) 删掉铺垫，从事实句或判断句起笔。(2) 铺垫里限定范围的成分留成状语，不随铺垫一起删（信息守恒）。(3) 开头提出问题，第二句就给出代价或回答的方向，不让问题悬着（07-elegance 出界清单的“卖关子”）。

不改：章首导读（F12）；小节开头直接给公式（“一致性窗口的一般形式是：”“把一条缓存记录写成一个三元组：”，自拟），动机在本节的概述里已经交代过。

**F5 概念的顺序：动机、定义、正例、反例** 【名家】【改稿】

触发标记：小节第一句就是加粗的定义句，例子在后面；定义之后只有正例，没有一个相近但不属于这个概念的例子；同一个定义在同一个语域里说了两遍。

Halmos 给新概念的顺序是 motivate、define、give examples、give counterexamples。SKILL.md 第五部分的通用规则也是先举例子，再下定义，最后形式化。竺可桢《大自然的语言》是范例：

> 竺可桢《大自然的语言》（据教材改写本）：杏花开了，就好像大自然在传语要赶快耕地；桃花开了，又好像在暗示要赶快种谷子。……这些自然现象，我国古代劳动人民称它为物候。……物候学记录植物的生长荣枯，动物的养育往来，如桃花开、燕子来等自然现象，从而了解随着时节推移的气候变化和这种变化对动植物的影响。

例子先到，名字后到，读者拿到名字时已经知道它指什么。梁思成《中国建筑的特征》也是九个特征逐条讲完以后才命名“文法”（11-exemplars E3）。

反例负责划边界。讲陈旧读时，把数据库事务里的脏读并排放出来：两者读到的都是不该读到的值，陈旧读读到的是曾经正确、后来已经改掉的值，脏读读到的是从来没有提交过的值（自拟）。最容易混的概念并排出现，比各自下一遍定义更清楚（07-elegance T4）。

定义说两遍，两遍要互补。Knuth：“Try to state things twice, in complementary ways, especially when giving a definition.”

> （自拟）一致性窗口是写入完成到所有副本更新之间的那段时间，也就是读请求可能拿到旧值的区间 $[t_w, t_w+\Delta]$。商品改价以后，详情页、搜索列表、购物车三处缓存各自在这段时间里的某一刻更新：先更新的显示新价，后更新的还显示旧价，用户在几个页面之间来回点，就会看到价格跳动。

第一遍是形式化的（时间段和区间），第二遍是例子，两遍互补。按口癖清单删掉这里的“也就是”是误伤：按 Knuth 的标准，它在两种形式之间搭桥，应当保留（P1）。要删的是同一语域里的同义复述（02-ai-tics A2）。

要调整顺序的例子：

> 原（自拟，诊断第 1 步那一节的首段）：**陈旧读（stale read）指底层数据已经改了，读请求拿到的却还是缓存里的旧副本。** 用上一节的话说，就是缓存和数据库对同一个键给出了两个答案。这个现象可以用一句老话概括：缓存省下的每一次查询，都是拿一致性换来的。某电商团队整理过 40 多起这样的事故，称之为“价格漂移”，也就是库里的价格已经改了，页面上还挂着旧价。最典型的一起发生在大促零点：……[1]。
> 改（示意，需作者确认）：某电商团队整理过 40 多起事故，称之为“价格漂移”，也就是库里的价格已经改了，页面上还挂着旧价。最典型的一起发生在大促零点：……[1]。**陈旧读（stale read）指底层数据已经改了，读请求拿到的却还是缓存里的旧副本。** 用上一节的话说，就是缓存和数据库对同一个键给出了两个答案。这个现象可以用一句老话概括：缓存省下的每一次查询，都是拿一致性换来的。

改后只挪了句子，删掉的只有“这样的”三个字：它原来指向前面的定义，定义挪走，它就没有先行词了，这是重排时最常见的事故（第六节）。加粗定义句原样保留（P1）。“可以用……概括”留到第三遍按 02-ai-tics B1 处理。这处改动换了作者的教学顺序，先做样板，再问作者。

不改：形式化小节（只给定义和公式的那类）以公式开头，动机已在本节的概述里交代；术语表、附录、API 文档这类查阅性文字，定义先行是体裁要求（08-genres）。

**F12 章首导读：一段，说清问题和顺序**（新增）【改稿】【经验】

触发标记：小节开头复述目录；“本节分为三部分”“下面按四个部分逐一展开”；导读预告了数量，正文又用“第一、第二”排队；导读写的顺序和正文的实际顺序对不上。

章首导读是体裁要求（P16），不按元话语删。好的导读只说这章回答什么问题、按什么顺序回答：

> 梁启超《敬业与乐业》开头（据教材本）：本题主眼，自然是在“敬”字、“乐”字。但必先有业，才有可敬、可乐的主体，理至易明。所以在讲演正文以前，先要说说有业之必要。

这段说清了题目的重心在哪里、先讲什么，顺序还带着理由。导读只放在章首和大节的开头，小节不重复。大节导读里的“先看……再看……最后……”在交代顺序，可以留，但要逐项核对它和正文的小节顺序。

改法：(1) 小节开头的导读删掉。(2) 数量预告改成顺序描述。(3) 导读和正文对不上，标“需作者确认”，不替作者调整正文的顺序。

## 三、段落内部

**F2 旧信息在句首，新信息在句尾** 【名家】【改稿】

触发标记：句尾落在空名词或回指上（……的过程、……方面、这一点、的问题、2.3 讲过这一点）；新信息在句首、旧信息在句尾（“这正是前面那条分界线”）；“让……的，是……”式的倒装把讲过的东西放在句尾。

Williams 把句尾叫作强调位置（stress position），读者在那里分配最多的注意力。每句从读者熟悉的信息开始，以新的、重要的信息结束，这句的新信息就成为下一句的旧信息。汉语是“话题—说明”结构，句末是常规焦点（汉语语法学的通行看法，具体出处未核），这条规则在中文里更顺手。杨振宁写虹，每句的主语都是上一句的结尾（07-elegance 范文赏析）。

> 原（自拟，小标题是“读从库”）：路由层只按“写入之后过了多久”来分流：一秒之内的读请求都发往主库，其余一律发往从库。这正是前面那条一致性分界线，路由层直接把它写进了配置。
> 改：路由层把前面那条一致性分界线直接写进了配置：读请求只按“写入之后过了多久”来分流，一秒之内的都发往主库，其余一律发往从库。

旧信息“前面那条一致性分界线”挪到句首接住上文，规则放在句尾，句尾正好落在小标题里的“从库”上。“这正是”的揭晓语气一并去掉（W16）。

> 原（自拟）：最后看接口。缓存怎么和业务代码、和数据库对接，经历了一个逐渐拆分的过程。
> 改：缓存和业务代码、和数据库之间的接口，是一步步拆开的。

句尾从“过程”换成“拆开”，本节要讲的就是怎么拆。“最后看接口”是报幕，小标题已经说了（F9）。节尾的结论句若是“**接口拆成了读、写、失效三条路径**”（自拟），改后的开头就和它用同一个动词，开头提出，结尾说清拆成了什么样。

> 原（自拟）：……能放进版本号的，要尽量放进键名里，2.3 讲过这一点。
> 改：……能放进版本号的，要尽量放进键名里（见 2.3）。

改法：(1) 把旧信息提到句首，常常要把两句并成一句（第一例）。(2) 句尾的空名词换成动词或实词（第二例）。(3) 回指收进括号（第三例，F11）。(4) 段尾也是强调位置，让它落在下一段要接的词上（F8 的例子）。

不改：“……的，是 X”把新术语放在句尾，合乎这条规则，例如“决定一条缓存什么时候作废的，是**失效策略**”（自拟，术语首次出现）。反过来，“让这套方案做到强一致的，是第 3 步的加锁”（自拟）应当改成正常语序：“第 3 步”是讲过的旧信息，放在句尾，强调就落空了。两句句式相同，区别只在句尾是新是旧。用户约定把引用标注放在句末时，照约定，不受这条约束。

**F3 话题链：一段之内，主语尽量不换** 【名家】【实测】【改稿】

触发标记：heads.py 抄出的句首在三个以上的名字之间跳；同一个东西换着叫（模型、该方法、这一框架、系统）；主语在人和抽象名词之间来回换。

Williams 讲 topic strings，Pinker 讲让主角保持不变。lieflat 的语料里，相邻句以同一名词开头的比例，AI 只有人的一半【实测】（未复核，见 01-boundaries P2）。

> 原（自拟，诊断第 1 步那一节的三段首句）：第一，这不是罕见现象。／第二，缩短过期时间，效果因读写比例而异……／第三，旧值会扩散。
> 改：读到旧值并不罕见。／缩短过期时间，效果因读写比例而异……／旧值还会扩散。

删掉领句以后，“这”失去了先行词（紧挨着的上文讲的是主从复制那一层），换回名词，三段首句都围绕“旧值”，跨段的话题链就有了。

换主语要有理由。朱自清《背影》写车站，主语在“我”和“他”之间交替：

> 朱自清《背影》（据教材本）：我们过了江，进了车站。我买票，他忙着照看行李。……他给我拣定了靠车门的一张椅子；我将他给我做的紫毛大衣铺好座位。

这段写的是父子之间的来回照应，两个主角交替出现是内容本身的形状，不改。技术文字讲两个对象的交互（客户端发请求、服务端回响应）时同理。

证据句以机构为主语也是正当的（P11）。这时话题链靠段首的判断句和反复出现的核心名词维持：查日志一段中间四句的主语都是机构，“旧值”却几乎每句都在，要处理的是证据怎么排（F8），主语不动。

改法：(1) 同一个东西只用一个名字（P2）。(2) 抽象名词做主语的句子，改回人或系统做主语（W3）。(3) 一段里主语换了三次以上，又说不出理由，多半是两个议题挤在一段里，按 F4 拆。

**F4 一段一个议题，要点落在段首一两句** 【名家】【改稿】

触发标记：骨架（只读前两句）里看不到这段的要点；段中出现第二个领句（“按……可以分成几层”“监控仪表盘也开始……”），主语换成另一类东西；段落长到五六百字以上（只是提示）；一段只有一句，而且只宣布下文。

Williams 把段落分成议题（issue）和讨论两部分。议题是开头的一两句，要点（point）通常落在议题的最后一句。第一句可以交代背景或提出问题，第二句要落下判断。

> 原（自拟，诊断第 1 步那一节的第二段）：写得频繁的数据格外容易读到旧值。缓存只在读的时候填充，写入却随时发生：两次读之间，库里的值可能已经改了好几轮。按旧值产生的位置，问题可以分成几层（图 3）。最外层是应用代码：……最里层是数据库的主从复制：……
> 改：在“按旧值产生的位置”处另起一段，其余不动。

前半段的议题是写得频繁的数据为什么容易读到旧值，后半段是旧值产生在哪几层。拆开后，第二段的首句带着排列的原则，是有信息的领句（02-ai-tics A6 的不改情形），图 3 紧跟其后，也正好配上。查日志一段（诊断第 2 步）也该在主语换类的地方拆开，拆开后，第二段首句里的“也”承接上一段。

要点放在段首。“缩短过期时间”那一段有两种改法：一种改成先举数字、最后用判断收束，另一种保留段首的判断，只调整证据的顺序（F8）。本卡取后者：读者扫读时只读前两句，要点放到段尾，扫读就失效了。段尾可以重申要点，前提是段首先有它。

并段的例子：“关于陈旧读，有三个值得记住的观察。”独占一段，只宣布下文，删掉（F7）。

不改：只有一句、但这句是判断的段落，例如用户约定的节尾加粗结论句；段首的加粗小标题加判断（“**查日志。** 监控只看错误率，读到旧值的请求却照常返回成功……”，自拟），小标题本身就是议题。

**F7 枚举写进句子，不预告数量** 【改稿】【实测】

触发标记：“有三个值得记住的观察”“能看出三件事”“有两点值得注意”“有三件事值得一提”，后面接“第一、第二、第三”或“一是、二是”。

lieflat 实测正文里的“第一，”人机没有差别（01-boundaries P7），要改的只是“先预告数量、再排队”这个组合。诊断第 1 步那一节的三个观察，删掉领句和序号以后，三段按“有多普遍、缩短过期时间挡得住多少、会不会扩散”递进（首句见 F3）。递进用“还”，不用“更麻烦的是”，原文没有“麻烦”这层评价。

同一个毛病也会出现在一段之内：

> 原（自拟，节选）：读这张表，能看出三件事。第一，失效策略从强一致到最终一致排成了一条线：……第二，大部分系统只在写入时删缓存：……这正是上一节说的“先写库，再删缓存”。第三，过期时间能不能设短，决定了旧值能存活多久。……能放进版本号的，要尽量放进键名里，2.3 讲过这一点。
> 改：这张表里的失效策略，从强一致到最终一致排成了一条线：……大部分系统只在写入时删缓存：……和上一节说的“先写库，再删缓存”一致。过期时间能不能设短，还决定了旧值能存活多久。……能放进版本号的，要尽量放进键名里（见 2.3）。

三条观察的首句各自带着判断，删掉序号以后，用“还”标出最后一条是追加。“这正是”改成“一致”（W16），句末回指改成括号（F11）。

保留数量的情形：数字本身是信息，后文还要用到它。例如“缓存层里最常见的 7 种失效策略”，表里正好 7 行，后文又说“把 7 种策略拆开来看”（自拟）。“第一”“第二”留给读者需要按编号回指的并列要求，比如安装步骤（P7）。

并列项的次序：由短到长，由简到繁，最重要的放最后（Williams 讲平衡时的建议）。例如列举 HTTP 缓存头，`no-store`、`no-cache`、`max-age` 三个短的并在一句里，带例子、最长的 `stale-while-revalidate` 放在最后单独成句（自拟）。

跨段的预告排队只拿到其中一段时，不改一半。例如“有三件事值得一提。”横跨四段，交给你的只是讲第二件的那一段，就把整块列进“范围外、建议一起改”（01-boundaries 第四节）。

**F8 证据按判断分组，不按来源排队** 【改稿】【实测】

触发标记：heads.py 抄出的句首全是机构名；相邻句都是“机构＋披露/发现＋逗号＋结果”（02-ai-tics A8）；段首的判断有两层意思，证据却按时间或来源排。

> 原（自拟，诊断第 1 步那一节的第五段）：第二，缩短过期时间，效果因读写比例而异：读到旧值的比例能明显下降，但降不到零。某电商团队把库存缓存的过期时间从 10 分钟缩到 30 秒，读到旧库存的比例仍是 6%，和缩短前几乎一样 [2]；一份社交平台的内部报告显示，……从 12% 降到 0.5% [3]；某开源项目的压测里，……从 30% 降到 8% [4]。
> 改：缩短过期时间，效果因读写比例而异：读到旧值的比例能明显下降，但降不到零。一份社交平台的内部报告显示，……从 12% 降到 0.5% [3]；某开源项目的压测里，……从 30% 降到 8% [4]。某电商团队把库存缓存的过期时间从 10 分钟缩到 30 秒，读到旧库存的比例仍是 6%，和缩短前几乎一样 [2]。

段首的判断有两层，“能明显下降”和“降不到零”，证据就按这两层排：两个明显下降的例子在前，用一个分号并列，电商团队“和缩短前几乎一样”的例子单独成句放在段尾。段尾落在“和缩短前几乎一样”，接上下一段的“旧值还会扩散”。数字和三个引用标号都没动，每个标号仍紧跟它支撑的句子。

几个数字差得远时，把它们并起来说清为什么不同（统计口径、检测方式、定义），这个“为什么”必须来自原文或出处。查日志一段的三组数字口径各不相同（312 起、41 条占 1.8%、“偶发”一档），原文没有交代原因，就不重组，只在“需作者确认”里请作者补上各自的口径。

改法：(1) 先找出段首判断里的层次，证据按层次排。(2) 打破相邻句同构，换一个更准的动词（“某团队测得”），或者换主语（02-ai-tics A8）。(3) 几组数字合成一句比较，前提是口径相同，或者原文说明了差别。

不改：证据本身在按时间讲一个演变过程（例如缓存一致性方案从定时过期、写后删除到订阅变更日志的几代演变，自拟），时间顺序就是论证的顺序。

## 四、段与段之间

**F9 段落靠回指衔接，不靠段首连接词和元话语** 【名家】【改稿】【实测】

触发标记：段首的然而、因此、此外、另外、与此同时（02-ai-tics A4，句首连接词当路标，AI 每千字 0.18、人 0.03，未复核）；“有了……再来看……”“接下来我们将介绍”；“最后看 X。”式的报幕。

Pinker 说元话语帮的是作者，读者理解路标多花的力气，比路标替他省下的还多（“Metadiscourse is there to help the writer, not the reader”）。Paul Graham 的建议是“use anaphora to knit sentences together”。衔接靠下面几种办法。

复述上一段或上一节末尾的名词，Williams 叫它 resumptive modifier（复述修饰语）。梁思成《中国建筑的特征》选段的第二段末句讲运用“文法”、用“词汇”，第三段接着起句：“这种‘词汇’和‘文法’到底是什么呢？”第三段讲完它们从哪里来，第四段起句又是“由这‘文法’和‘词汇’组织而成的这种建筑形式”。

用一个真问题过渡。问题必须是读者此刻真会有的，答案紧跟在后面。

> 竺可桢《大自然的语言》（据教材改写本）：物候现象的来临决定于哪些因素呢？
> 梁思成《中国建筑的特征》（据教材本）：这种“词汇”和“文法”到底是什么呢？归根说来，……

竺可桢的问句自成一段，下面四段依次回答纬度、经度、高下、古今。梁思成下一句就用“归根说来”作答。两处都只问一次，没有卖关子。

用一个总括的说法把上文收住，再转出新内容，Williams 叫它 summative modifier（总括修饰语）。华罗庚的“这是小事，但这是引子”用一个“这”收住整段泡茶，再转到生产管理。

> 梁启超《敬业与乐业》（据教材本）：我征引儒门、佛门这两段话，不外证明人人都要有正当职业，人人都要不断地劳作。
> 梁思成《中国建筑的特征》（据教材本）：这许多例子说明各民族各有自己不同的建筑手法，……

“这两段话”收住前面孔子和百丈禅师的两段引语，“这许多例子”收住窗子、圆亭、牌楼、华表几组对照，收住之后再说出判断。

要改的过渡：

> 原（自拟）：有了读写两条路径的划分，再来看缓存层里最常见的 7 种失效策略。先用一句话介绍它们：
> 改：缓存层里最常见的失效策略有 7 种：
> 原（自拟）：按这个判据，把 7 种策略拆开来看。大多数策略都同时涉及读写两条路径：
> 改：按这个判据拆开来看，大多数策略同时涉及读写两条路径：

前一例先回顾上文、再宣布下文，后面的表格自己会说明每行只有一句。后一例的第一句只说“我要拆开来看”，并进第二句做状语即可。

连接词留给读者看不出来的关系：转折、让步、反直觉的因果。以“所以”“最后”起头的段落，处理各不相同（下面四例自拟）。“所以，缓存层对外只承诺两件事：读得快，旧值有上限。”和“所以热点键会花大量时间排队等锁。”承接推理（P6），保留。“最后看接口。”只是报位置，删掉（见 F2）。“最后把上面几种策略合起来：”里的“合起来”说明本节在做综合，只删“最后”。

改法：(1) 删掉连接词，看上下文是否接得上。接不上，补一个回指的名词，不要补另一个连接词。(2) 连接词移到主语后面，或者换成轻的“也”“还”（02-ai-tics A4）。(3) 元话语式的过渡句整句删掉，必要时把它的内容并进下一句做状语（上面第二例）。

不改：两半都带着内容的对照式过渡，例如“上一节讲的是数据存在哪里，这一节讲数据什么时候作废”（自拟），它收住上文的同时说出了新的问题，属于总括式的衔接；推理里的“所以”“因此”（P6）；前向引用“放到下一节讲”（P16）。

**F6 一个例子贯穿到底** 【名家】【改稿】

触发标记：每个小节换一个新例子，而前面的例子换个角度就能用；后文用到前面的例子，却没有任何回指，读者认不出是同一个。

Halmos 的螺旋式组织：讲第二个概念时，要从它的角度把第一节“as nearly completely as possible”重看一遍。华罗庚《统筹方法》是范例，泡茶的例子从甲、乙、丙三种办法一直用到箭头图（11-exemplars E1）。周志华《机器学习》的西瓜数据集从第一章用到后面各章（E23）。读者每次只需要看这个熟悉的例子多了哪一层。

比喻也可以贯穿。梁思成把中国建筑的惯例法式叫作“文法”，把梁、柱、枋、檩这些构件叫作“词汇”，宫殿、庙宇是“大文章”，山亭、水榭是“小品”，最后提出各民族建筑之间的“可译性”，喻体始终在语言这一个领域里（11-exemplars E3）。贯穿的比喻要用同一套说法（07-elegance T3）。

改法：例子是内容，改稿时不替作者换例子，也不删例子（信息守恒）。能做的是在后文第一次重用旧例子的地方加一句轻回指（“回到那个改价的例子”，自拟），前提是两处确实是同一个例子。起草时先选一个能撑到底的例子再动笔。

不改：按领域组织的综述（例如分关系数据库、键值存储、搜索引擎、消息队列四块讲存储系统，自拟），每个领域需要自己的例子；旧例子撑不住新概念时，不要硬套。

**F11 回指章节要轻** 【改稿】

触发标记：“3.1 说过”“4.1 讲过”“索引一节讲过”“前面讲过”“如前所述”起句；一段里两处以上整句回指；括号回指放在句末，而它只支撑句子的前半。

一部中文技术书稿的一章里，用“讲过”“说过”回指的地方有十几处，有的一段两处。下面是同类的自拟例子：

> 原（自拟，节选）：更彻底的办法是让写入方直接作废缓存。2.1 说过，失效最重要的性质是由知道数据变了的一方发出。……3.2 讲过，订阅变更日志的方案就是这样做的；……
> 改：更彻底的办法是让写入方直接作废缓存。失效最重要的性质是由知道数据变了的一方发出（见 2.1）。……订阅变更日志的方案就是这样做的（见 3.2）；……

2.1 的这个说法若是那一节的结论句，读者大概率还记得，括号就够了。“最重要的性质”是原文的判断，并句时不能丢。

括号放在它支撑的那个说法后面，不一定在句末。例如“缓存里写死的假设会随着数据规模变大而过时（见 2.2），库存服务里也有一例：……”（自拟），回指放在第一个分句末尾。放到句末，读者会以为 2.2 讲过整句话。

不改：做定语的回指（“3.1 的概念”“第 3 章讲过的缓存穿透”“上一节那条慢查询”，自拟）；读者需要回去翻的长距离回指，写成完整的一句。同一页里回指的写法要有变化，不要全换成括号（不造新口癖）。

## 五、节尾

**F10 节尾给判断，不给摘要** 【名家】【改稿】

触发标记：加粗结论句能从小节标题猜出来；把各段的话题挨个缩写一遍；结论句前面加“一句话概括：”“这里只需要记住一个原则：”；“这不仅是……更是……”式的升华（02-ai-tics A11）。

节尾是全节的强调位置。Williams 说一篇文字的要点在引言末尾出现之后，结尾还要再出现一次。节尾的最后一两句要给出本节新增的判断。用户约定每个小节以一句加粗结论收尾时，这句结论就是它。成立的节尾，有的划出边界：

> （自拟）**一个延迟数字要连同百分位、负载、命中率和硬件一起报；差距小于重复测量的波动时，不能说哪种方案更快。**

有的说出代价：

> 竺可桢《大自然的语言》讲物候对农业的重要性，段尾是（据教材改写本）：而那年春初种的花生等作物仍然是按照往年日期播种的，结果受到低温的损害。如果能注意到物候延迟，选择适宜的播种日期，这种损失就可能避免。

有的推出一个做法或不显然的结论：

> 竺可桢讲纬度的一段，段尾是：所以在华北常感觉到春季短促，冬天结束，夏天就到了。
> 竺可桢讲高下的一段，段尾是：在华南丘陵区把热带作物引种在山腰很成功，在山脚反不适宜，就是这个道理。

这两段各讲一个因素，段尾收住的是这个因素，和小节的节尾同理。诊断第 1 步那一节的结论句（“所以失效要由写入方主动发出，不能只靠过期时间”）也属于这一类。

有的把没解决的问题交出去。正文已经交代跨机房同步的细节“留到下一章再讲”，结论句就收在“**写入方和读取方都得设防，因为单靠过期时间挡不住复制延迟**”（自拟）。

检验节尾，依次问。标题检验：这句话能不能从小节标题猜出来？能，就重写。支撑检验：判断必须由本节正文支撑，本节给不出判断，问题出在正文，标出来交给作者，不在结论句里补正文没有的论断。摘要检验：句子是不是在按段落顺序列话题？重申本节的主要判断可以，挨个缩写各段不行。

半句摘要、半句判断的节尾：

> 原（自拟，讲缓存记录形式化的小节）：**一条缓存记录是 $(k, v, e)$：存哪个键、存什么值、什么时候过期。新旧由数据库判，不由缓存判。**
> 改（示意，需作者确认）：**新旧由数据库判，不由缓存判，而且只在记录过期、读请求回源时判一次。**

前一句从标题就能猜出来，后一句才是本节新增的判断。补上的“只在记录过期、读请求回源时判一次”要能在本节正文里找到出处。作者可能希望节尾保留三元组的复述，所以标需作者确认。

重申主要判断的节尾不改。F7 那张表所在小节的结论句若是“**失效策略从强一致一直排到最终一致；越往后，写入越便宜，读到旧值的窗口也越长。**”（自拟），它几乎逐字重复了正文的第一条观察，可它重申的是本节的主要判断，带着取舍，从标题猜不出来，通过了全部检验。梁启超《敬业与乐业》末段的“今天所讲，敬业即是责任心，乐业即是趣味。”也是重申，它换了两个日常的词，没有把各段挨个缩写一遍。

结论句前的领句删掉：

> 原（自拟，诊断第 1 步那一节的末段）：写入侧怎么改、读取侧怎么防，放到下一节讲。这里只需要记住一个原则：**副本越多……**
> 改：写入侧怎么改、读取侧怎么防，放到下一节讲。**副本越多……**

“一句话概括：**缓存决定读得多快，失效决定读得多准。**”（自拟）同理，加粗已经告诉读者这是结论。

不改：非加粗的前向引用（“写入侧怎么改、读取侧怎么防，放到下一节讲。”）；章末小结（P16）。章末小结可以总结，每节的结论句不能只是总结。

## 六、不经询问不要做的结构调整

在交给你的范围之内，可以调整段内证据的顺序、拆段、删掉空转的领句和元话语（SKILL.md“改动的范围”）。下面这些调整要先问作者，或者先拿一段做样板给作者看：

1. **跨节搬运、合并小节、改标题层级。** SKILL.md 明确要求先问。
2. **改变作者的教学顺序。** 定义先行改成例子先行（F5 的陈旧读一例），哪怕方向合乎 F5，也先做一段样板。
3. **挪动或拆散加粗的定义句和结论句。** 术语首次出现时的加粗、中文译名、英文原名都是信息（P1）。结论句只能按 F10 删掉摘要的部分，换成另一个判断要标“需作者确认”。
4. **替换、删除或新增例子和比喻。** 例子是内容。统一一个比喻的说法（把“外层、里层”统一成“远、近”）要动多处正文和图注，先列进“范围外、建议一起改”。
5. **把段落改成表格，或者把表格改成段落。** 两个方向的转换都会改变版面。用户约定了短条目写成段落，或者限定了表格的行数，更要先问。
6. **按判断重组证据时，补原文没有的说明。** 口径、原因、时间，原文没有的一个字也不补，标“需作者确认”（F8）。

反面的例子（自拟）：把“陈旧读”一节改成先讲大促零点那起事故，方向合乎 F5，可在重排中删掉了加粗的定义句和英文原名 stale read，给那起事故补上原文没有的“损失上百万”，把“写得频繁的数据格外容易读到旧值”改成“这个问题格外严重”（容易和严重是两个论断），还引入了原稿没有的破折号。结构动得越大，越要逐句核对。

重排之后，逐项复核：指代词（这、这样的、上述、它）的先行词是否还在前面；每个引用 key 是否仍紧跟它支撑的句子；图表是否仍在正文第一次提到它之后出现；“也”“还”这类递进词在新的顺序里是否还成立；加粗结论句是否仍在节尾。
