# 中文润色知识库：目录、路由与维护

这个知识库配合 skill `tuiqiao`（推敲）使用。skill 本身只放行为规则、改稿流程和一张路由表；规则的展开、成批的例句、口癖词典、替换词表、范文和改稿案例都放在这里，按问题读取。结构参照了 GitHub 上的 goutoujunshi（狗头军师）：薄内核加分层知识库，每次只读当前问题需要的一到三张卡，不整库载入。

知识库随 skill 一起安装：卡片在 skill 目录的 `references/` 下，公版选段在 `references/exemplars/` 下，扫描脚本在 `scripts/zh_style_scan.py`。

| 02-ai-tics | AI 口癖词典：A 档强信号 A1–A13、B 档成片才改 B1–B13、C 档已推翻 C1–C10，各模型特点 | 判断一处写法是不是口癖、有哪几种改法 |

## 按问题找卡

改一段 AI 起草的稿子，先读 01，再按 02 的 A 档扫一遍；具体的词查 04，语法理由查 03。段落结构不顺、论证串不起来，读 06。标点读 05。想加一点文采，读 07，找范文读 11。文本是论文、README、设计文档或博客，先读 08 看哪些规则要松要紧。想看一整段的改法，读 09。用户问依据，读 10。

一次最多读三张。读完发现需要另一张，再增量读，不要一开始就把整个目录读进来。

## 证据等级

每个条目后面标一个或几个等级，用来判断这条规则有多硬。

- **【实测】** 有语料对比或统计数据。多数出自 lieflat-less-ai-tone 的语料（未公开，未复核），只用来分档，不当定论。
- **【规范】** 国家标准、词典或权威语法著作，如 GB/T 15834—2011、《现代汉语词典》、吕叔湘与朱德熙。
- **【名家】** 写作名家的主张（余光中、思果、朱光潜、Williams、Pinker 等），是经验之谈。
- **【经验】** 社区文章和开源 skill 的归纳。
- **【改稿】** 在一部中文技术书稿的改稿中验证过。

规则冲突时，【规范】和【改稿】优先于【经验】；【实测】只决定一个口癖该放哪一档，不决定一句话改不改。

## 维护规则

这些规则参照了 goutoujunshi 的知识库治理办法，按中文技术写作的情况改写。

**新增口癖条目之前，先抽样。** 用 `zh_style_scan.py` 或正则在至少两份人写的技术文本和两份 AI 稿里各抽 20 处命中，逐处读上下文，再看频率。lieflat 记录的六次测量失误，都出在先看数字后看命中。只在一种模型里出现的词，写进 02-ai-tics 的模型一节，不进 A 档。

**每条规则都写“不改”。** 新规则没有想清楚例外，就先不收。

**有时效的内容写日期。** 模型口癖、开源项目版本、标准的实施日期，写明“截至某年某月”。新模型发布后，先更新 02-ai-tics 的 B 档和模型一节，A 档一般不动。

**改编号或删卡片时，查所有引用。** SKILL.md 的路由表、00-index 的卡片表、各卡的 related 字段和正文里的交叉引用都要同步。可以在本地把知识库下载下来，用 `grep -rn "R15\|02-ai-tics"` 一类命令查。

**版权。** 在世作者和 1975 年及以后去世的作者，每条最多两句短引，每句不超过 50 字；1974 年及以前去世的作者可以存较长的选段，存进 `exemplars/`，文件开头写明出处、核对办法和公版依据。开源项目（均为 MIT 许可）的规则用自己的话转述，例句注明出处。

**不收私人文本。** 例句和改稿案例一律虚构，或者取自公版选段和已发表作品的短引。想拿自己的稿子做案例，放在自己的副本里，不提交到公开仓库。某个项目专用的体例写进那个项目的说明文件，SKILL.md 第六部分只讲怎么找、怎么用。

**改脚本后同步说明。** 改了 `zh_style_scan.py` 的子命令或检测项，同步改脚本开头的用法说明、SKILL.md 第二部分和相关卡片里对它的描述。

**卡片自己守规矩。** 卡片本身就是范文，写和改卡片时按 SKILL.md 和各卡的规则来。改完用 `zh_style_scan.py scan` 扫一遍卡片本身。
