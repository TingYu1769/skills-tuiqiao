# 中文技术写作：去 AI 味、改用词、理行文、有文采

这个 skill 管四件事：去掉 AI 的口癖，改准用词，理顺行文，写出技术文章该有的文采。改稿时的顺序正好反过来：先理行文，再改用词和口癖，最后才谈文采。结构不对，字句改得再细也要返工。

本文件只放边界、流程、路由和一份精简规则。规则的展开、成批的例句和范文都在知识库里，按问题读取。

## 知识库

知识库随本 skill 一起安装，路径都相对于本 SKILL.md 所在的目录：`references/` 下是 00-index 到 11-exemplars 共 12 张卡，`references/exemplars/` 下是公版范文选段，`scripts/zh_style_scan.py` 是扫描脚本。用读文件的工具直接读，例如 `references/02-ai-tics.md`。

每次只读当前问题需要的一到三张卡，读完发现还需要别的再增量读，不要整库载入。读不到时，按本文件第五部分的精简规则工作，并在回复里说一句知识库没接上。

## 一、三条边界

改稿最常见的失败是改出新毛病。下面三条优先于所有规则。

**信息守恒。** 事实、数字、公式、符号、引用 key、图表编号、术语、限定词、否定、条件、归因，一个不增，一个不减。改完后，每个实词都要能在原文里指出出处。不补例子，不补数字，不替作者编经历、感受或新的论断。原文缺证据或说法不准，在批注里标“需作者确认”，不自己填。限定词表达证据强度，只删叠在一起的重复保险。

**语体不降级。** 目标是正式、平实的现代书面语。不加“说白了”“讲真”“挂了”“大家管这叫”，不硬塞“我觉得”，不加感叹号，不为了有人味写反问。技术文字里，中性和克制本身就是人的声音。

**不造新口癖。** 把“正是”全换成“就是”，把破折号全换成冒号，只是换了一种口癖。改完统计替换进去的词，同一个替换词一页里出现三次以上，就换一种改法（删掉、换主语、改结构）。原稿没有的标点习惯，改稿也不要引入。

**优先级。** 三条边界最高，其次是第六部分的用户约定，最后是其余规则。规则打架时选改动更小的那条；拿不准是否命中规则，就不改。

## 二、改稿流程

改 AI 起草的稿子，按五遍走。自己起草时，动笔前读 06-flow，写完按第五遍和验收清单自检。

1. **锁定。** 列出不能动的东西：事实、数字、公式、引用 key、术语、图表位置、标题层级。读 01-boundaries 的保护清单。
2. **理行文。** 只读每段前两句，看论证能不能串起来，再看段与段怎么接、节尾落在哪里（06-flow）。结构问题先改。
3. **改用词与句法**（03-word-syntax、04-replacements）。
4. **去口癖、改标点**（02-ai-tics、05-punctuation）。
5. **添文采**（07-elegance）。放在最后，而且克制：一节里有一两处恰好的比喻、对照或判断就够了。原文已经克制准确，就不加。

能跑代码时，先用扫描脚本定位候选，改完再核对：`python3 scripts/zh_style_scan.py scan FILE` 列出强信号候选、短主语后的逗号和分号密度，`skeleton FILE` 抽每段前两句，`heads FILE 行号` 列句首查话题链，`diff 改前 改后` 核对数字、引用 key、代码、公式是否一致，以及改后多出来的高频词。命中只是候选，要回到上下文判断。

**改动的范围。** 在交给你的范围内，可以调整段内证据的顺序、拆段、删空转的领句和元话语，也可以在相邻两段之间挪一两句，批注里写明挪了什么。跨节搬运、合并小节、改标题层级、把段落改成列表，先问。一处毛病牵涉范围外的内容，不要只改一半，列进“范围外、建议一起改”。你的知识和原文冲突时，不悄悄改事实，标“需作者确认”并写明该核对哪个出处。

**交付格式。** 用户要对照看时，每段先给原文，再给改后；改动处行尾标“⇐ 改N”（一段只占一行时，标记按先后排在段尾），N 全文连续。正文之后逐条批注：原句、改句、一句理由、规则编号（F7、W4、A1、R15 等）。每段列出“没改的”和理由，用户靠它判断有没有漏看或过度修改。文末汇总“需作者确认”和“范围外、建议一起改”。用户只要成稿就只给成稿。整节或整章的改写，先拿一小段做样板（格式见 09-cases），认可了再铺开。

## 四、保护清单（摘要）

看着像毛病、其实不改的写法，完整的 P1–P17 和例子在 01-boundaries。最常误伤的是：下定义的“即”“称为”和术语首现的加粗；同一术语一名到底（为避重复换词，读者会以为换了东西）；证据性限定（通常、可能、几乎、据……报告）；决定真假的“之一”、限制性定语、量词“存在”、计数和引入新对象的“一个”、消歧的“被”、实验条件“在……上”；已成术语的“性”“化”“度”；推理里的“因此”“所以”；真实顺序里的“首先”“第一”；纠正读者真会有的误解的“不是 A，而是 B”；带来新推论的“这意味着”；分号的正当用法；交代证据来源的主语和动词（“该厂商 2025 年 3 月披露”“第三方评测测得”）；段首加粗小标题；被动、名词化、长句、句内真排比、问句、比喻本身；交叉引用、章首导读、章末小结；引用的原文、轨迹、提示词、代码一律照录。

## 五、精简规则（知识库读不到时用）

**行文。** 开头直接进入事实或有代价的问题，不用“随着……的发展”铺垫；新概念先例子，再定义，再形式化（F1、F5）。旧信息在句首，新信息在句尾，前一句的结尾接成后一句的开头（F2）。一段之内主语尽量不换（F3）。一段一个议题，要点落在前两句（F4）。枚举写进句子，不预告“有三个观察”再排“第一、第二、第三”，递进用中性的“还”“也”（F7）。证据按判断分组，几个数字为什么不同，理由必须来自原文（F8）。段落靠复述上段末尾的名词、一个真问题、一个总括的指代来衔接，删“接下来我们将介绍”式元话语，“然而”“因此”留给看不出来的关系（F9）。节尾给判断（边界、代价、反直觉推论、留给下一节的问题），可以重申本节的主要判断，不把各段挨个缩写一遍，不升华（F10）。章节回指用括号，紧跟它支撑的说法（F11）。

**用词与句法。** 万能动词加抽象名词还原成动词：进行重排序 → 重排，实现了提升 → 提升了；“给出定义”“给出证明”是数学惯例，保留，“给出分数”后接公式时写“算出分数 $S=…$”（W1）。“对应”“具有”“存在”“扮演……角色”换成真实的关系，“一一对应”要数两边的项数（W2）。“被”默认去掉，“被称为”改“称为”（W4）。删话题壳：对于……来说、从……的角度看、在……方面（W5、W7）。“通过……使”会吞掉主语（W6）。句首“作为 X”的 X 必须就是主语（W8）。长前置定语拆成后置小句（W9）。“这一＋名词”改“这个”“这种”（W10）。不计数的“一个”删掉（W11）。硬造的“性”“化”“度”改回形容词（W12）。“正是”“恰恰”“格外”“尤其”先删掉念一遍（W16）。“便”“之”“其”“此”成堆时换成白话（W17）。

**口癖强信号。** 翻案腔（不是 A 而是 B、与其说、说到底）；复述式推论（这意味着、换言之，后句与前句同义）；句首评论语（值得注意的是、值得一提的是；作者只要最小改动时，可以只补一个回指词）；段首连接词连用；话题壳；空转领句（“主要包括以下几点：”）；元话语；相邻句同构；概括盖掉具体（同段已有数字却写“显著提升”）；拟人化喻体（“像一位永不疲倦的助手”）；金句收尾和升华；越证据断言（证明了、彻底、首次）；模糊归因（研究表明，没有引用）。成片才改的：“可以”虚化（作者自己选定的说法前加“可以”；能力义、规范文字里的“应、宜、可”、引入比喻的“可以叫它作”都留）、限定词叠用、顿号长串、引号造词、装饰性加粗、黑话和工程腔（收口、兜底、落盘）、短主语后单独加逗号。已被推翻、不能据此改的：句长不够参差，同一名词反复出现，被动和名词化本身，三项并列，问句和比喻本身。

**标点。** 破折号只用于正文里的解释说明，不制造揭晓式停顿。冒号只用在有停顿处，一句之内不套用两个。分号的用途：内部有逗号的并列分句、冒号后的分项列举。GB/T 15834 还允许用于非并列多重复句的第一层，这类句子在技术文里多半拆成两句更清楚。说不出用途的，改逗号或句号。不设每段几个的上限，一组真正平行的定义用分号并排，比拆成几个同构的短句好。经验阈值：全文每千个汉字超过一个分号，就逐个查一遍用途。短主语后面不单独加逗号（“缓存，是用空间换时间的办法”），较长的主语、话题句（“这个问题，下一节再谈”）除外（PN16）。引号不为强调而加。中英文、中文与数字之间加空格。

**文采。** 技术文章的文采是精确和经济。让动词承重（T1）；往准里炼字，“影响”换成真正发生的“拖慢”“掩盖”（T2）；比喻只取一面、写明取哪一面、一个比喻用到底、不当论据（T3）；用对照成文（T4）；长句装条件和机制，短句下判断（T5）；四字格和文言一次一个（T6）；替读者说出反对意见再转折（T7）；用条件圈住断言然后说死（T8）；具体胜过“层面、维度、范式”（T9）；在关键数字旁用一句短话停一下，不新增论断（T10）。不要的“文采”：抒情、拟人叙述、造势排比、强化副词、升华、拿比喻当论据、追求平仄、换说法求变化、卖关子、死喻黑话、四字格连排、用文言替代白话。

## 六、用户约定

用户或项目自己的体例，优先于本文件的通用规则。常见的约定有：引用怎么写（比如 `[@key]` 放在句末），全书沿用的符号和术语表，正文用不用破折号，短条目写成列表还是段落，小节末尾要不要一句加粗的结论，表格多大，章节回指怎么写。约定可能写在项目的 CLAUDE.md、AGENTS.md 或单独的风格说明里，也可能是用户在对话里交代的。动手前先找这些约定，找到了就照办，和通用规则冲突时听约定。找不到，就按通用规则改，第一次交付时列出默认采用的几条体例，请用户确认。改稿中途用户新提的约定，后面的段落都照办。

## 验收清单

1. **信息守恒。** 数字、公式、引用 key、术语、限定词、否定、归因逐一对过；能用脚本比对的用 `diff` 比对。
2. **行文。** 只读每段前两句，论证串得起来；节尾结论句给的是判断，不能从标题猜出来。
3. **口癖。** 强信号逐项查过，命中处逐个看过上下文。
4. **标点。** 每个分号说得出用途；没有新增破折号；短主语后没有单独的逗号；没有为强调加的引号和加粗。
5. **没造新口癖。** 替换进去的词没有在一页里扎堆。
6. **保护清单。** 一个都没被误改。
7. **朗读。** 不拗口，没有电报句，没有口语词，没有感叹。
8. **用户约定。** 第六部分都满足。
